    HOW TO PLAY

    Every game in CPU RUSH is a sequence of decisions. You are shown the current state, you make one call, and you are told immediately whether it was right and why. This page has the full rules for each one — click a heading to open it.

    0 · The basics: scoring, hints, controls
    • Start a mission: type your name and USN, choose a Mode, then an Algorithm / Policy for that mode, then press START MISSION. Your name and USN are remembered on this browser.
    • One decision at a time. Each mission is a queue of decisions. You answer, you get instant feedback ("✓ Correct" or an explanation of what was wrong), and the next decision appears.
    • Scoring. Points per correct answer differ per mode (50–100). A perfect run adds a large bonus (300–500). You also earn a time bonus that shrinks the longer you take, and lose points for wrong answers. Your final score goes to the shared leaderboard (top 20).
    • Streak. Consecutive correct answers build a streak, shown in the results.
    • HINT reveals the answer for the current decision and costs points (−40 to −75). Hints are recorded on your result.
    • Controls. 1–9 pick an option or card, D deploy (CPU scheduling), H hint, Enter confirm where a confirm button exists.
    • XP. Score converts to XP and levels, shown at the top of the home screen. Winning a mode with every algorithm unlocks achievements.
    1 · CPU Scheduling

    You get a set of processes, each with an arrival time, a burst (how long it needs the CPU), and a priority. Repeatedly pick which process the CPU runs next, until every process has finished. You may only pick a process that has already arrived.

    AlgorithmPick next
    FCFSThe process that arrived earliest. Ties → lower id first.
    SJFAmong the arrived processes, the one with the shortest burst. Non-preemptive: the running process finishes its burst.
    RR (q = 3)The process at the head of the ready queue. It runs for 3 units, then goes to the back of the queue.
    PriorityThe arrived process with the highest priority — lower number = higher priority.
    2 · Memory Management — Page Replacement

    You get a reference string (a sequence of page numbers) and a fixed number of frames. For each reference decide HIT (the page is already loaded) or MISS, and if it is a miss, which page gets evicted — the victim.

    PolicyVictim
    FIFOThe page that has been in memory the longest (loaded earliest).
    LRUThe page that was used least recently.
    OptimalThe page that will not be used for the longest time in the future. Needs the whole string up front — a theoretical best case.
    ClockA hand sweeps the frames. If a frame's use bit is 1, clear it and move on; evict the first frame whose use bit is 0.

    If a frame is still empty, the page is loaded there with no eviction. A page already in a frame is a hit and changes nothing.

    3 · Disk Scheduling

    The disk head sits on a track and there is a queue of pending track requests. Each turn, pick the next request to service.

    AlgorithmPick next
    FCFSIn arrival order, no reordering at all.
    SSTFThe request closest to the current head position — shortest seek first.
    SCAN (elevator)Keep moving in the current direction, serving every request on the way, then reverse at the end.
    4 · Memory Allocation — Holes

    Free memory is split into holes of different sizes. A request arrives; pick the hole the strategy would choose.

    StrategyChoose
    First fitThe first hole (lowest address) that is big enough.
    Best fitThe smallest hole that is big enough — leaves the least waste, but creates tiny leftovers.
    Worst fitThe largest hole — leaves the biggest remainder.
    5 · Deadlock Management — Banker's Algorithm

    You get an Allocation table (what each process holds), a Max table (what it will ever need), and Available resources. Remaining Need = Max − Allocation. Each turn a process requests resources; decide GRANT or DENY so the system stays SAFE.

    Deny if the request exceeds that process's remaining Need, or exceeds what is currently Available. Otherwise pretend to grant it and run the safety check: repeatedly find a process whose Need fits within Available, let it finish and release everything it holds. If every process can finish, the state is safe → GRANT. If some process can never finish → the state is unsafe → DENY, even though the resources are physically free.

    6 · Virtual Memory — Demand Paging

    Each reference shows a page number and whether it is a read (R) or a write (W). Choose the correct outcome.

    OutcomeWhen
    HITThe page is already in a frame. Nothing changes.
    PURE FAULTThe page is legal but not loaded — the OS must fetch it. If all frames are full, FIFO picks the victim.
    COW FAULTA write to a page marked shared. The OS makes a private copy first, so the other process keeps the original.
    PROTECTION FAULTThe reference is outside the process's valid page range (beyond maxPage) — an illegal access. The process is killed, not paged in.
    7 · File System Allocation

    A disk of numbered blocks, some already in use. Files arrive one at a time and must be placed in order. Click the free blocks you want, then press CONFIRM ALLOCATION. Any placement that obeys the method's rule counts as correct — you do not have to guess one specific layout.

    MethodLegal placement
    ContiguousOne unbroken run of adjacent free blocks, exactly the file's size.
    LinkedExactly size free blocks, anywhere on the disk. The links follow block order.
    IndexedOne index block plus one block per data block = size + 1 free blocks. The lowest-numbered block you pick is the index block.

    Clicking a block that is already in use tells you so. If your earlier choices fragment the disk until the current file has nowhere legal to go, a SKIP FILE button appears so the run can still finish — but a skipped file scores nothing.

    8 · Synchronization — the five topics

    This mode walks a real execution, one step at a time, and asks you to call what happens. Each topic is a separate run.

    The Critical-Section Problem

    Two processes interleave: ENTER the critical section, EXIT it, or do WORK outside it. For each event say whether it is LEGAL or a VIOLATION. It is a violation when a process enters while another is already inside (mutual exclusion broken), or when a process exits without holding the critical section. Work outside is always legal. The three requirements a solution must meet: mutual exclusion (never two inside at once), progress (someone can always get in if the section is free), and bounded waiting (no process waits forever).

    Peterson's Solution

    Each process i runs: flag[i] = true; turn = j; while (flag[j] && turn == j) ; then the critical section, then flag[i] = false;. You are shown flag[0], flag[1] and turn at the moment a process reaches its while-loop, and must say whether it ENTERS (the condition is false) or SPINS (the condition is true). Because a process only sets turn to the other process, both can never pass at once — that is how it guarantees mutual exclusion without any hardware help.

    Hardware Support for Synchronization (TSL / Swap)

    An atomic TSL (test-and-set-lock) instruction reads the lock and writes 1 in one indivisible step. Predict whether a process ACQUIRES the lock (TSL returned 0 — the lock was free) or SPINS (returned 1 — someone else holds it), and whether a release is legal. Releasing a lock you do not hold is an error. Because TSL is atomic, two processes can never both observe 0 — the second necessarily sees 1. That is the whole point of hardware support.

    Mutex Locks

    A mutex has acquire() and release(). For each call predict one of three outcomes: ACQUIRES (the mutex was free), BLOCKS (another process holds it, so this call waits), or ERROR (this process already holds it — a plain mutex is not recursive, so a second acquire is a bug, not a wait). A release() by a process that does not hold the mutex is also an error.

    Semaphores

    A counting semaphore S with two atomic operations: P(S) (wait) and V(S) (signal). P decrements S if S > 0 and continues; if S is 0 it blocks and joins the queue, leaving S at 0. V increments S — unless a process is blocked, in which case that process is woken and immediately consumes the unit, so S stays the same. For each operation predict the value of S afterwards. A binary semaphore (S limited to 0/1) behaves like a mutex.
